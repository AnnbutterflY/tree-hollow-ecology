# 同济大学悬铃木树洞地图

以表格档案为基础的独立 React 网页：草绿地图、生态网络和三人联机互动故事。首页采用手绘树林、粉笔标题、橙红圆环及分层鼠标视差。

## 直接打开

解压运行包后，双击 `打开地图.html`。必须保留旁边的 `assets` 文件夹。地图与同机故事演示无需联网；三手机联机需要通过 HTTPS 网站访问并联网。

源码目录中入口为 `dist/打开地图.html`。`dist/index.html` 适合静态服务器或 GitHub Pages。整个 dist 可用于 GitHub Pages 发布。默认显示游戏首页；网址加 ?map=1 可直接进入地图。

## 使用

- 拖动地图、滚轮缩放；手机支持拖动和双指缩放。
- “全景 / 区域 / 近观”切换视角，档案底部按钮定位当前树木。
- 搜索编号或选择 A–J 分区；搜索结果仍受分区限制。
- 悬停显示预览，点击打开档案；手机采用底部档案面板。
- 点击空白或 Esc 关闭档案。天气切换保留所选树木。
- 切换拓片与实拍，点击图片放大；详情向下滚动查看属性、生物和备注原文。
- 右上信息按钮查看数据说明。地址加 `?dev=1` 开启图像比例坐标读数（非经纬度）。校准后编辑 src/data.json 中 position，再重新构建。

## 表格优先

指定《未命名表格 (1).xlsx》的 SHA-256：
`74a41c1535c8ab66fa4bbcc6499c38cfc3884b16aaa934d54271c2e039b566ea`

180 条唯一记录、180 张实拍、76 张拓片。F1–F43，G1–G22，其他编号也严格按表格。晴天已填写 114 条，阴天 113 条，雨天 55 条；高度 43 条、朝向 8 条。

图片按 B/C 列锚点及该行 A 列编号归档，未使用素材文件名、拓片角标或视频示例数量替换。拓片保留原色、原尺寸与透明底，73 张通过图形匹配对应压缩包原 PNG；J11、J12、J18 保留表格图像，未猜测匹配。A4 角标与上缘重叠，裁去重叠带，未补画。180 张实拍均为竖向，其中 G14 使用竖向裁切，其余按原拍摄方向校正。

第二版将地图轮廓转换为 SVG，晴天白底、浅钢蓝建筑、灰色背景层次，滚轮支持 1–8 倍缩放。悬停有拓片的树点显示透明预览，无拓片档案仅提供实拍选项。附近虫子使用原图鉴素材并依照当前天气记录展示，不代表实时观察。A 列保留圆点强调，移除地图固定标签；详情页显示“树洞密集处”文案；声音是模拟树皮、枯叶摩擦的轻微合成窸窣音效，首次点击后启用，右上可静音。

data-audit.json 包含源文件哈希、图片源行列和哈希、裁切范围、展示文件 displayFile 与参考位置。

- 表格没有坐标。全部点位来自位置图同名标注，仅供参考，待现场核对。位置图多出的 F44、F45、G23–G29 不新增档案。地图采用图像配准，不是地理测绘。
- 未提供拓片不等于无树洞；天气空白不等于生物缺席。
- 高度、朝向保留原文，包括 0、负值和多组高度。没有推定日期。
- 生物图标来自提供的图鉴，缺图类群用文字与统一标记。图标表示类群，不表示个体数；备注数量不分配给任一天气。
- 晴/阴/雨是观察分类，不是实时天气。雨天主题采用雨后底图，数据仍取“雨天生物”列。

## 开发

需要 Node.js 20.19+ 或 22.12+ 与 pnpm。

```sh
pnpm install
pnpm dev
pnpm test
pnpm build
node scripts/standalone.mjs
```

- src/main.jsx：地图、标记、预览、档案、筛选、天气和弹窗组件。
- src/model.js：天气读取、搜索、缩放边界。
- src/style.css：响应式布局和天气主题。
- src/data.json：180 条数据与参考位置。
- public/assets：校园地图、实拍、拓片与物种图标。

源码包包含生成的数据与全部展示素材，无需原始压缩包即可构建。scripts/prepare_assets.py 是第一版整理归档脚本；第二版素材处理见 upgrade_media.py、vector_map.py 与 public 下的审计 JSON。重跑这些提取脚本需要原始输入及父目录参考素材；普通开发只需构建，不要重跑第一版提取脚本覆盖新素材。

用 Python + openpyxl 核对原工作簿：

```sh
python scripts/verify_workbook.py "未命名表格 (1).xlsx"
```

原文件声明范围错误地写为 A1:A1，脚本重置范围后逐行读取，避免漏行。

## 三台手机联机

1. 三人打开同一个线上网址。点击“开始游戏”。
2. 一人创建房间，另两人输入六位房间码，或打开邀请链接后加入。
3. 各自选择不同角色、点击准备；由房主出发。每台手机只持有并提交自己频道的证据。
4. 三人完成采样、碎片汇合、线索交接、独立判断、最终符号和各自长按确认后，同步解锁 B2。

联机使用随项目提供的 PeerJS 1.5.5 和公共 PeerJS Cloud 信令，WebRTC 数据通道由房主手机维持。建议三台手机连接同一 Wi-Fi，房主保持前台。不提供 TURN 中继，某些校园网络、网络隔离和跨运营商环境可能无法连通；面向正式展览应配置可靠信令与 TURN 服务。没有要求摄像头、麦克风、定位或注册。

伙伴刷新后，在同一浏览器重新加入原房间可恢复频道；房主刷新后，可点击“恢复我创建的房间”，伙伴会尝试重新连接。房间仅在房主浏览器保存，不是云端永久存档。离线席位只可在出发前由房主释放。

已验证：三个独立浏览器客户端通过实际 PeerJS Cloud/WebRTC 完成全流程；伙伴刷新重连保留阶段与角色。尚未进行三部实体手机及跨运营商测试。28 项自动测试涵盖档案完整性、地图位置、角色隔离、断线推进门槛及三方解锁。

- src/Homepage.jsx、Homepage.css：树林、前景、标题、圆环、按钮独立分层，鼠标平滑追随，移出回中，支持减少动态效果设置及手机触控。
